# 启动进度协议（startup.json）

供 Tauri / 其他外部外壳在启动 Python web 服务时展示进度条。

## 概述

启动链路涉及两个进程：

```
ctl.py（父进程）          run.py + app.py（子进程）
  ├─ env (5%)               ├─ imports (50%)
  ├─ port (10%)             ├─ config (55%)
  └─ frontend (40%)         ├─ factory (60%)
                            ├─ app (70%)
                            ├─ uvicorn (80%)
                            └─ lifespan (90%) → done (100%) → cleanup
```

各步骤通过原子写（`.tmp` + `os.replace`）更新同一文件 `.kongming/web/startup.json`。
子进程启动时会读取父进程写入的文件，合并已完成步骤，保证进度不回退。

## 文件路径

```
<project_root>/.kongming/web/startup.json
```

- 启动过程中持续更新
- 启动成功后**立即删除**
- 启动失败后**保留**，供外壳读取错误信息
- 下次启动时重新创建（覆盖旧文件）

## JSON Schema

```json
{
  "version": 1,
  "steps": [
    { "id": "env",      "label": "加载环境配置",   "pct": 5,   "status": "done" },
    { "id": "port",     "label": "检查端口",       "pct": 10,  "status": "done" },
    { "id": "frontend", "label": "构建前端",       "pct": 40,  "status": "running" },
    { "id": "imports",  "label": "加载模块",       "pct": 50,  "status": "pending" },
    { "id": "config",   "label": "读取配置",       "pct": 55,  "status": "pending" },
    { "id": "factory",  "label": "装配运行时",     "pct": 60,  "status": "pending" },
    { "id": "app",      "label": "创建应用",       "pct": 70,  "status": "pending" },
    { "id": "uvicorn",  "label": "绑定端口",       "pct": 80,  "status": "pending" },
    { "id": "lifespan", "label": "启动线程管理器", "pct": 90,  "status": "pending" },
    { "id": "ready",    "label": "服务就绪",       "pct": 100, "status": "pending" }
  ],
  "current_step": "frontend",
  "pct": 40,
  "status": "running",
  "error": null,
  "updated_at": 1714459200000
}
```

### 顶层字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `version` | int | 协议版本，当前固定 `1` |
| `steps` | array | 10 个步骤的状态列表 |
| `current_step` | string\|null | 当前正在执行的步骤 id |
| `pct` | int | 0-100，当前累计进度百分比 |
| `status` | string | 全局状态，见下表 |
| `error` | string\|null | 失败时的错误信息 |
| `updated_at` | int | 毫秒级 Unix 时间戳 |

### 全局 status 值

| status | 含义 | 文件是否保留 |
|--------|------|-------------|
| `running` | 启动进行中 | 保留，持续更新 |
| `done` | 启动成功 | **立即删除** |
| `error` | 启动失败 | 保留，`error` 字段含错误信息 |

### 步骤 status 值

| status | 含义 |
|--------|------|
| `pending` | 未到达 |
| `running` | 正在执行 |
| `done` | 已完成 |
| `error` | 该步骤失败（仅当前步骤可能出现） |

## 10 个步骤定义

| id | label | pct | 所在进程 | 失败场景 |
|----|-------|-----|---------|---------|
| `env` | 加载环境配置 | 5 | ctl.py | 目录创建失败（权限） |
| `port` | 检查端口 | 10 | ctl.py | 端口已被占用（直接退出，不写 error） |
| `frontend` | 构建前端 | 40 | ctl.py | `npm run build` 失败 |
| `imports` | 加载模块 | 50 | run.py | uvicorn 未安装 / import 错误 |
| `config` | 读取配置 | 55 | run.py | YAML 不存在或格式错误 |
| `factory` | 装配运行时 | 60 | run.py | 依赖模块 import 失败 |
| `app` | 创建应用 | 70 | run.py | 密码未配置 / 路由注册失败 |
| `uvicorn` | 绑定端口 | 80 | run.py | 端口被占用 / 权限不足 |
| `lifespan` | 启动线程管理器 | 90 | app.py | ThreadManager.start() 异常 |
| `ready` | 服务就绪 | 100 | app.py | — |

**注意**：`port` 检查失败时 ctl.py 直接退出（不写 error 到 startup.json），因为此时 startup.json 已被创建并写入了 `env` 步骤，但 `port` 不会写入。外壳应结合进程退出码判断。

## 外壳接入指南

### Rust (Tauri) 伪代码

```rust
use std::fs;
use std::thread;
use std::time::Duration;

fn poll_startup_progress(project_root: &Path) -> Result<(), StartupError> {
    let progress_path = project_root.join(".kongming/web/startup.json");
    let mut was_running = false;

    loop {
        // 文件不存在：未启动 或 已成功（cleanup 删除了）
        if !progress_path.exists() {
            if was_running {
                // 之前在跑，现在没了 → 启动成功
                return Ok(());
            }
            // 还没开始，继续等
            thread::sleep(Duration::from_millis(300));
            continue;
        }

        let data: StartupJson = serde_json::from_str(&fs::read_to_string(&progress_path)?)?;

        match data.status.as_str() {
            "running" => {
                was_running = true;
                // 更新 UI：进度条 = data.pct，文字 = current_step label
                update_progress_bar(data.pct, &data.current_step);
            }
            "done" => {
                return Ok(());  // 不太会走到这（cleanup 会先删文件）
            }
            "error" => {
                return Err(StartupError::ServerFailed(
                    data.error.unwrap_or_default()
                ));
            }
            _ => {}
        }

        // 超时检测：30 秒无更新 → 卡住
        let now_ms = chrono::Utc::now().timestamp_millis();
        if now_ms - data.updated_at > 30_000 {
            return Err(StartupError::Timeout);
        }

        thread::sleep(Duration::from_millis(300));
    }
}
```

### 状态机

```
外壳启动
  │
  ├─ spawn python -m hosts.web.ctl start
  │
  ├─ 轮询 startup.json（300ms 间隔）
  │    │
  │    ├─ 文件不存在 + 从未读到 running → 继续等
  │    ├─ status=running → 渲染进度条
  │    ├─ 文件消失（之前是 running）→ 启动成功，切主窗口
  │    ├─ status=error → 显示错误弹窗
  │    └─ updated_at 超 30s 未变 → 提示"启动似乎卡住了"
  │
  └─ 同时可轮询端口（TCP connect）作为备用就绪检测
```

### 常见错误信息

| error 值 | 含义 | 用户操作 |
|----------|------|---------|
| `Frontend build failed: ...` | npm build 失败 | 检查 Node.js 安装 / `web/` 目录 |
| `web.enabled is false` | 配置禁用了 web | 设置 `web.enabled=true` |
| `create_app failed: ...` | 应用装配失败 | 检查密码配置 |
| `uvicorn.run failed: ...` | 端口绑定失败 | 检查端口占用 |
| `ThreadManager.start() failed` | 异步初始化失败 | 查看 `.kongming/web/server.log` |
| `Web process died during startup` | 子进程崩溃 | 查看 `.kongming/web/server.log` |
